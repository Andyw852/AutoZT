### 确认的缺陷（详见报告）
- **P0 BUG-1** `autozt/mcp.py::_cycle` 内 `apply()` 只传 `dry_run/actions/cursor`，**丢掉 tt/material/step/status**；而 `_apply_actions` 用这套 args 重新加载状态算 cursor → 与 inspect 阶段的收窄态 cursor 必然不等 → **带作用域的 `cycle(execute=true)` 100% 返回 stale_plan、零动作执行**。文档推荐姿势失效。
- **P0 BUG-2** `autozt/collect.py::run_remote` 严格 UTF-8 解码子进程输出；非 UTF-8（GBK）→ UnicodeDecodeError 被吞 → **rc=1 且输出为空**（命令本身 exit 0）。已打断本机 3 个测试套件（反复出现 `0xd2`）。修法：`errors="replace"`。
- **P1 BUG-3** `autozt/agentgate.py::agent_log_load` 只 `except OSError`，读到坏字节即抛栈；`setting/.tf_agent_log.jsonl` 已有撕裂行（偏移 221258，并发追加无锁）→ `autozt act log` 永久不可用。
- **P1 BUG-4** `_profile_tool_names()` 无 else 兜底 → **未知 `AUTOZT_MCP_PROFILE` 静默放开到全量 24 个工具**（fail-open）。`PROFILE=readonly` 是常见误用，真只读开关是 `AUTOZT_MCP_READONLY`。
- **P1 BUG-5** 仓库根 9 个垃圾目录。7 个 `C:Users...tf_autodeps_*remoteXstep1` 成因已实证：`tests/suite_autodeps.py` 用 `mkdtemp()` 拿 Windows 绝对路径 → `workflow.py:675` 用 `shlex.quote()`（POSIX）不加引号 → bash 吃掉反斜杠 → 在仓库根建出无分隔符目录。`wsl.localhost/` 同理（UNC 当相对路径）。`%SystemDrive%/`（内含真实 Windows Caches *.db）**来源未定位**。`%SystemDrive%` 未被 .gitignore 覆盖。
- **P2** AGENTS.md 写「16 个技能」，实际 20 个（漏 `cohp-cogito`/`eph-qe-cpu`/`fc-fit`/`zt-dft-cpu`）；8 个技能无 README（band/ke/phonon 等高频技能在内）→ 铁律 0 的前置文档悬空；mace↔mlff 命名混用。
- **P2** 测试：8 suite + 4 用例失败。其中 `suite_asset_lookup` 断言硬编码 `/`、`suite_supercell` 模板路径写成 `_common/mace/`（实际 `_common/mlff/`）、`suite_agentgate` 依赖 Unix-only `termios` 是**测试自身问题**；`suite_autodeps/prov/poscar_sync` 是 BUG-2 连带。

### 环境限制（影响结论边界）
- `wsl.exe` 被本机安全策略拦截（PROGRAM BLOCKED BY SECURITY POLICY），**无法在 Linux 侧验证**；所有执行均在 Windows 侧 Python 3.12 + `\\wsl.localhost\...` 上完成。
- pytest 的 tmpdir teardown 会被沙箱批量删除守卫中断，需 `-p no:tmpdir` 或显式 `--basetemp`。
- Bash 工具的 PATH 缺 coreutils，需前置 `export PATH="/c/Users/user/.workbuddy/binaries/PortableGit/versions/1.2.0/usr/bin:$PATH"`。
