# Translating runtime messages

PhonoAgent can print its messages in English. The command reference (pa --help) is fully
translated; runtime messages are being migrated incrementally. This page records the
procedure so the migration is safe and repeatable.

## Mechanism

- phonoagent/i18n.py provides t(zh, en). When PHONOAGENT_LANG (or LANG) starts with "en"
  the English form is printed, otherwise the Chinese one. Unknown or missing translations
  fall back to Chinese, never to an empty string.
- Display-layer mappings are used where rewriting the producer would be risky:
  i18n.diag() maps collector diagnostics (for example "converged（5/3 段）" ->
  "converged (5/3 stages)") and preflight.EN_HINTS holds the English text of the
  pre-submission hints.
- scripts/i18n_report.py reports progress. Its percentage counts only whole strings
  wrapped in t(); display-layer mappings and format-string wrapping are not counted, so the
  number is a lower bound.

## Migration recipe

1. Prefer whole-string wrapping:

       print(t("已生成 %s", "generated %s") % name)

2. For a multi-line print, wrap the ENTIRE expression, not just its first line. A partial
   edit of a concatenated message was exactly what broke the CLI once:

       print(t("%s: 已生成输入，未提交。检查后运行  pa -p %s -j %s start  提交。"
               "%s: inputs generated, not submitted. Review, then run pa -p %s -j %s start")
             % (tag, name, step))

   Safer for long messages: assign the translated text to a variable first, then print it.

3. Wrap only user-facing output. Strings used for parsing (markers, keys, greppable
   tokens) must stay unchanged, and the remote collector's tokens are matched by the local
   side, so prefer mapping them with i18n.diag() instead of editing the collector.

4. After each batch:

       python3 -c "import ast; [ast.parse(open(f).read()) for f in (...)]"
       pa skills && pa schema --strict
       pytest -q
       python scripts/i18n_report.py

   The first two catch the syntax-level mistake that a partial multi-line edit produces.

5. Keep each batch small and commit it with the strings it touched, so a regression is
   easy to bisect.
